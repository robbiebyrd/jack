# TouchOSC Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Make Jack's OSC work directly with TouchOSC controls: float ports, buttons (press acts, release ignored), per-pose button addresses, fader feedback on `/jack/<motor>`, and a mouth-mode toggle.

**Architecture:** Two independent changes, run in parallel:
- **Task 1, the input side**, in `show_commands.py` (`osc_command`). Button arguments are stripped or interpreted before the existing `_build`, and a release (0) returns `None`, which `handle_osc` ignores silently.
- **Task 2, the feedback side**, in `osc_feedback.state_messages`. It adds `/jack/<motor>` and `/jack/mouth/mode/show` in the spec's order.

Task 3 updates the README.

**Spec:** `SPEC.md` "### TouchOSC support" (and "### OSC replies and feedback").

## Global Constraints
- On `main`, one commit per task with `git commit --only … -- <paths>` and the co-author trailer. Never push.
- TDD: tests first, capture RED. Output must be pristine under `.venv/bin/pytest -q -W error`.
- **Button rule:** an argument that is a number (int or float) or a bool is a button value. Non-zero or `True` acts; `0`, `0.0` or `False` is ignored silently, with no log and no reply. A string or a second argument is a 400.
- **Feedback order:** for each motor (mouth, hand, pivot, elbow): `/jack/<motor>` (float), `/jack/<motor>/volts` (float), `/jack/<motor>/max_hold` (int). Then `/jack/mouth/mode` (str), `/jack/mouth/mode/show` (float 1.0 or 0.0), `/jack/mumble` (int).
- **HTTP is unchanged.** The new per-pose address and the numeric mode values are OSC-only; HTTP keeps its routes and returns 404 for `/<motor>/pose/<name>`.

## Review Focus
1. **A TouchOSC momentary button** on `/jack/rest` sends 1 and then 0, so it must rest exactly once and log nothing. Tested in Task 1.
2. **A float port** `21601.0` subscribes to port 21601; `21601.5`, `0.0` and `70000.0` are 400s. Tested in Task 1.
3. **A momentary button on `/jack/mouth/mode/show`** sends 1 and then 0, which switches to show and then back to live. This is the specified behaviour, documented in the README. Tested in Task 1.
4. **A fader on `/jack/hand`** gets `/jack/hand` feedback of 0.0 after the dead-man timeout, so the fader drops back. Tested in Task 2 (state_messages from a status with no command).
5. **Feedback on value commands:** a pose shows `/jack/<motor>` 0.0 and its volts in `/volts`. Tested in Task 2.

### Task 3: README (after Tasks 1–2)

**Files:** `README.md`

- [ ] Add a "TouchOSC" subsection under the OSC docs:
  - **Connection:** host `10.10.0.54`, send port `9000`, receive port your choice (e.g. `21601`).
  - **Subscribe button:** send `/jack/subscribe` with your receive port as its value (int or whole float), pressed at least every 60 s; or set `JACK_OSC_REPLY_PORT` and send no value.
  - **Faders:** `/jack/hand`, `/jack/elbow` and `/jack/mouth` use 0–1; `/jack/pivot` uses −1–1, so set the fader range to −1…1.
  - **Buttons:** `/jack/rest`, `/jack/<motor>/rest` and `/jack/<motor>/pose/<name>` act on press and ignore release.
  - **Mouth mode toggle:** a toggle button on `/jack/mouth/mode/show`. Not a momentary button: its release switches back to live.
  - **Feedback:** faders follow `/jack/<motor>`, so they drop to 0 when Jack rests a motor; `/volts` and `/max_hold` can drive labels and LEDs.
  - **Caveat:** say plainly that this is based on general TouchOSC behaviour and was not tested against a specific TouchOSC version.
